# 自建中继的设计审查

| 原方法与影响 | 发行版的处理 | 验收依据 |
| --- | --- | --- |
| 家庭网络拿不到可入站地址，或直连路径速度不稳 | NAS 和电脑各自通过 OpenSSH 出站，VPS 只在回环桥接两段 | 独立的专用 sshd，真实 TLS 测试服务双向传输并验证字节 |
| 现场脚本写死机器、账号与端口，复制到新电脑要编辑脚本 | `init nas/client` 生成设备独立密钥；命令行集中管理端口和主机身份 | 同配置重复注册查询同一公钥；配置冲突报错 |
| 客户端独有密钥若没有角色限制，VPS 可能成为通用跳板 | 专用 sshd 使用 `MaxSessions 0`，NAS 仅允许 remote 到指定监听，电脑仅允许 local 到指定目的地；每把钥匙另有对应端口限制 | CI 检查生效配置与回环绑定，注销设备后再次连接会失败 |
| 现场定时拉起控制台程序会闪窗，反复启动可能抢同一个端口 | Windows 登录任务直接使用 pythonw；子进程无控制台，关闭监督进程也会回收 SSH；锁和退避管理实例 | Windows 真实登录任务安装、重复安装、停止、立即启动与卸载 |
| 旧启动器观察“该端口已监听”就待命，会将无关程序误认成已有中继 | 运行锁属于当前私有配置；端口被其他程序占用会显式报告冲突；不给未知进程发送终止信号 | 用空闲临时端口放置第二个监听器测试 |
| SSH 的保活只验证到 VPS，单看监听容易掩盖 NAS 掉线 | 两端 `doctor`、VPS `status` 分层检查；`probe send/ack` 测到最终文件 | SSH 进程、NAS 端口、文件哈希分别输出 |
| 用全局版本号差、逻辑字节数估算剩余文件和时间，遇到历史删除、同内容复用会失真 | 业务层统计由 Drive 处理，项目提供随机文件互验；网络传输和同内容本地复制分别计时 | 当相同校验值已存在时，记录逻辑落盘字节并不能推出公网流量 |
| 重连间隔一致时大量客户端会一起冲击 VPS | 心跳、超时、带随机扰动的指数退避，最长约 60 秒 | 集成测试重启 VPS、断开 NAS，再次校验双向数据 |
| VPS 中转不是端到端的应用认证 | SSH 固定 VPS 主机密钥，Drive 同时校验证书中的 NAS 名称 | 用可信测试 CA 和指定测试域名跑 TLS，部署后用真实 Drive 探针验证 |

## 如何测量收益

在同一台电脑、同一目录和可用时段下，交替测试原链路与中继。每次用新的随机文件；至少分开测“电脑 → NAS”和“NAS → 电脑”。可以先用 1 MiB 测发现延迟，再用 8 或 16 MiB 观察稳定传输。记录文件生成时间、另一端首次完成校验的时间、样本字节数、VPS 对应连接的收发字节差和采样时长。另一端预先等待 `ack` 才能把发现和传输一起计入观察窗口。真实传输完成后才开始 `ack`，它报告的只是本地校验等待。

`平均业务速率 = 已验证样本字节数 / 源端写入完成至目标端校验完成的秒数`。跨设备时间戳的测量需要校时；也可以由同一观察者计时。若多个同步任务共用中继，SSH 连接计数器涵盖这些任务及协议开销。新副本若被 Drive 从已有文件本地复用，逻辑完成量可远超 VPS 带宽。TCP 握手延迟、版本游标和文件发现延迟各自回答不同问题。

## 协议边界与后续优先级

- 即便两个 SSH 用户都禁止 shell，反向转发的目标仍由持有 NAS 凭据的那台设备指定；VPS 可以约束它申请哪个监听地址，不能用 `PermitListen` 证明设备内的目的服务身份。独立设备密钥和 Drive TLS 都需要保留。
- 一台公网 VPS 的可用性和出入站带宽构成上限。先看单方向文件样本和成本，再考虑第二节点。双节点自动切换还需要独立保活、同一 NAS 的目标身份和切换滞后策略，v0.1 使用单节点。
- 默认只转 Drive 桌面同步协议。网页分享、首次网页登录、移动端或特定单点登录流程可能有额外的 HTTPS 依赖，应在真实 DSM 上逐一验收。
- 公共工具没有稳定的官方全局任务计数 API。版本相关的客户端数据库解析可作为日后独立、只读、明确标注版本的诊断工具。生产上的文件锁、Git 对象只读和多套同步器共享目录都应由文件层排查，传输服务不会改业务文件权限。
- 后续最值得做的是给 DSM 提供签名的软件包和可复现的真实版本兼容矩阵，再收集匿名、同口径的线路测试。对多 NAS、多节点需求，可在独立端口和状态模型有了集成覆盖后扩展。
